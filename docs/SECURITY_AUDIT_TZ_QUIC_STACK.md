# ТЗ — аудит QUIC-стека ssh3-c (`src/event/quic/*`)

> Техническое задание для команды аудита («Wasm Tunnel», pass-3). Базируется на методе
> pass-1/pass-2 (docs/SECURITY_AUDIT_2026-10-17.md, docs/SECURITY_AUDIT_PASS2_2026-10-18.md).
> Целевая аудитория — аудитор, не видевший этой сессии: документ самодостаточен.

## 1. Контекст проекта

- **Проект:** `nagual2/ssh3-c` — независимая C17 (nginx-стиль) реализация SSH3:
  SSH-сессии/форварды поверх HTTP/3 extended CONNECT (RFC 9220) на QUIC (RFC 9000).
- **Слои (снизу вверх):** `src/core` (буферы/строки/пул/лог) → `src/os/unix` + `src/os/win`
  (платформенный: epoll/WSAPoll, named pipes, ConPTY) → **`src/event/quic` (QUIC-транспорт,
  ~11.7k LOC — предмет этого ТЗ)** → `src/h3` (HTTP/3 + QPACK) → `src/ssh3` (SSH3-каналы,
  auth JWT/Basic/OIDC, сессии, sftp, forwards) → `app/` (mains клиента/сервера).
- **Ключевое архитектурное решение (DEPS-QUIC.md):** чужих QUIC-стеков нет. Транспорт —
  собственный, портирован из QUIC-модуля **nginx 1.31**; TLS/криптография — через
  **OpenSSL 3.5 QUIC TLS API** (`SSL_provide_quic_data`, `SSL_handle_events`, QUIC-методы).
  Референс исходников nginx: `C:\Git\temp\ssh3-c\refs\nginx\` (read-only копия 1.31).
- **Пров/интероп:** wire-совместимость с go-форком подтверждена интероп-легами; релиз
  v0.4.1 живёт на WSL/Mint/Windows.

## 2. Почему этот слой — самый важный

Каждый входящий UDP-датаграмм — включая всё **до аутентификации** — разбирается здесь:
парсинг форм пакетов, защита заголовков (HP), расшифровка payload (AEAD), фреймы.
Исторические уязвимости QUIC-реализаций (quic-go, nginx QUIC, ngtcp2) — ровно этот класс.
Ошибка в слое роняет **и клиент, и сервер** — это фундамент, а не модуль. Аудиторы
pass-1/pass-2 слой не читали (оба отчёта: «the largest unread block») — этот пасс
закрывает пробел.

## 3. Скоуп и порядок чтения

3.1. **Инвентаризация (первым делом):** таблица файлов `src/event/quic/*` (wc -l,
подсистема, роль) — аналог §2 pass-2. Точную разбивку подсистем фиксирует аудитор —
документ сам себя описывает.

3.2. **Приоритет 1 — pre-auth parsing:** длинный/короткий заголовки пакетов, varints,
version negotiation (VNEGO подделка), retry/stateless-токены, Initial-пакеты, защита
заголовков (HP: вычисление маски, ключи), AEAD nonce/packet-number reconstruction
(масштабирование PN, key phase, key update), обработка неудачи расшифровки
(должна ли быть PROTOCOL_VIOLATION/тишина — сверка с RFC 9000 §12, 17).

3.3. **Приоритет 2 — фреймы:** все типы RFC 9000: границы, unknown-type skipping по
длине, обязательные порядки (CRYPTO упорядочивание, ACK ranges: валидность
интервалов, дубли, gap-логика), MAX_DATA/MAX_STREAM_DATA/MAX_STREAMS — accounting
без underflow и с корректным возвратом квот, STREAM fin/reset/stop_sending —
полнота полузакрытых состояний, CANCEL/RESET взаимодействие с s3_ssh3-слоем выше.

3.4. **Приоритет 3 — состояние соединения:** loss detection/PTO (таймеры — в проекте
кап 500 мс на тик: не ломает ли PTO), ретрансмиссии (спurious-логика), congestion
control (какой реализован — фиксированное окно/NewReno?), idle timeout
(сверка с заявленным 24h/`--max-idle-timeout`), connection migration/refusal,
transport parameters (парсинг/валидация обеих сторон), keys update
(односторонее обновление — синхронизация фаз).

3.5. **Приоритет 4 — стык с OpenSSL QUIC API:** последовательность
`SSL_provide_quic_data` (тотальный порядок CRYPTO-байтов), `SSL_handle_events`
поллинг (кто и когда), ошибки API (пропагация vs заглатывание), экспорт ключей
`EXPORTER-SSH3` (живёт выше, но границы — здесь).

3.6. **DoS:** неаутентифицированный флуд (сколько состояния создаётся до ключей),
рост памяти на соединение/поток (капы: 64 потока, 8 udp-пиров — из P7.4/P8 —
проверить и здесь), таймерные структуры при тысячах соединений.

3.7. **Огороженные Linux-only фичи:** UDP_SEGMENT/GSO (должен быть fallback —
проверить, что guards не текут в путь FreeBSD/OpenBSD — заготовка под F6-порты),
io_uring — за флагом и вне release.

## 4. Метод (пас 1/2 + обязательные пробы)

- Static review: grep-directed чтение с `file:line` якорями; каждое утверждение —
  прочитано в дереве, не унаследовано; всё недочитанное — в §not-covered честно.
- Commit-level: `git log --oneline v0.4.1..main` + история слоя от предыдущих
  аудит-пассов (если упоминается) — только с ре-чеком.
- **ОБЯЗАТЕЛЬНЫЕ пробы (отличие от pass-1/2):**
  1. fuzz-харнес на парсер пакетов (stateful: последовательности датаграмм, не только
     одиночные; mutation + structured corpus; ASan+UBSan; цель ~1M+ инпутов);
  2. прогоны существующего ctest (42/42 linux-release и linux-asan — база до правок);
  3. если логика loss/PTO тестируется синтетикой — прогнать сценарии.
  Отчёт обязан разделить: «утверждено статикой» vs «подтверждено пробами».

## 5. Классы дефектов, которые ищем

OOB/underflow/целочисленные обёртки в varint-арифметике и ACK-диапазонах; UAF
(таймерные узлы, пул соединения — прецедент idle-close UAF `527b3f7`); двойная
обработка пакета/фрейма (replay в пределах PN space); несоответствие ключевых фаз
(key update); утечки fd/памяти на путях ошибок; DoS-состояние до аутентификации;
несоответствие RFC 9000 (что разрешено — что отклоняется).

## 6. Окружение и база

- **Baseline:** `main` на момент старта (после `349bde9`/`822dcb1`; tag `v0.4.1`),
  зафиксировать SHA в отчёте.
- Сборка: `cmake --preset linux-release && cmake --build --preset linux-release`;
  база — **ctest 42/42 linux-release и 42/42 linux-asan** (зелёные до/после любых
  пробных правок). OpenSSL 3.5: `~/opt/openssl-3.5` (native) либо системный trixie.
- WSL (Ubuntu 24.04) + patchelf/fakeroot при deb-сборках (не входит в скоуп аудита).

## 7. Deliverable

- `docs/SECURITY_AUDIT_PASS3_QUIC_<DATE>.md` по структуре pass-2:
  scope/method → change-set map → чтение по приоритетам §3 (таблицы с якорями и
  вердиктами) → probes (§4) → **findings** (таблица `F3-x` / `Info`, severity,
  предмет) → **coverage/limitations** (честный not-covered список с порядком
  следующего пасса).
- Отдельно: **regression probes** на фиксах pass-2 (P2-1 peer bound — QUIC-слой
  получает его из заголовка: проверить, что клампирование не подделывается на этом
  уровне; P2-3 replay — jti выше, но exporter bytes рождаются здесь: убедиться,
  что exporter корректно привязан к соединению).
- Если в ходе пасса найдены дефекты — **фиксы отдельно**: ветка `fix/pass3-quic`,
  TDD (тест → фикс), коммиты по одному дефекту, ctest 42/42 обеих конфигураций;
  отчёт report-only остаётся чистым (прецедент pass-2 §10).

## 8. Критерии приёмки пасса

1. Документ с якорями по каждому приоритету §3.2–3.4 и честным §limitations.
2. Минимум один harness + прогон с числами (инпуты/время/репорты).
3. Найденные дефекты: ветка fix/*, зелёный ctest, PR.
4. Явный вердикт: «memory-safety defect found/not found» и остаточный риск-список.
