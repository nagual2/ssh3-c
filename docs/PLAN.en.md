# ssh3-c — plan for client and server development
> Languages: [RU](PLAN.md) · EN (this file) · [DE](PLAN.de.md)

## 1. Goal position: "OpenSSH among Linux systems"

The goal of the project is for ssh3-c to eventually occupy the place in Linux systems that OpenSSH holds, with a corresponding license. In concrete terms, this means the following features:

| № | OpenSSH feature | ssh3-c goal | Status |
|---|-----------------|-------------|--------|
| 1 | Language — pure C | C17 | decided (2026-10-01) |
| 2 | License — permissive (OpenBSD/ISC family, no copyleft) | own code — BSD-2; borrowed nginx code — BSD-2 (compatible); `THIRD-PARTY-NOTICES.md` | decided |
| 3 | Dependencies — system ones only (libcrypto, zlib) | only `libcrypto` (OpenSSL ≥3.5 QUIC API) | decided (DEPS-QUIC.md) |
| 4 | Protocol layer — project's own code | QUIC+H3 — our source code (nginx adaptation) | decided |
| 5 | Packages in distributions, man pages, systemd units | deb/rpm/apk/ipk, man, socket activation | phase P7 |
| 6 | Coexistence with predecessors (OpenSSH replaced telnet/rsh, it did not erase them) | ssh3 — a separate package next to OpenSSH, not a replacement | phases P7–P8 |
| 7 | Quality acceptable for distribution security teams | fuzzing, sanitizers, audit (R2), interop matrix | phases P6+ |

The protocol specification is `SSH 3.0 alpha-00` (the primary source is the Go implementation francoismichel/ssh3; the nagual2 fork inherited the protocol). The IETF track is closed (2026-10-16, owner's decision): the upstream is dead, draft-michel-remote-terminal-http3-00 has expired — the spec becomes a project document (rev nagual2/1, stage (0) P8 in §4).

## 2. Language and license (fixing decisions)

- **C17** (replacing the previous "C++20"): both references (OpenSSH, nginx) are C; libstdc++ is absent in base systems (Alpine base, embedded/OpenWrt); the C ABI is stable. Polymorphism is implemented via function pointers (the `ngx_connection_t` pattern), not classes.
- **Windows client (P9) — also C17** (confirmed by the Pilot on 2026-10-10): the portable code is already C17 with coverage (ctest/fuzz/interop), the new code is only the os-layer and the CLI scaffold; C++ has been rejected again — the libstdc++ argument does not apply to Windows, but there is no counterargument: all system interfaces (WinSock, ConPTY, named pipes) are C APIs. The port model is modeled after `src/os/win32/` in nginx 1.31.7 (6,147 lines of pure C): platform-specific code entirely in `src/os/win/` (a mirror of `os/unix/`), `s3_errno.h` with `S3_E*`→Win code mapping (`S3_EAGAIN=WSAEWOULDBLOCK`), an I/O table based on function pointers (WSARecv/WSASend on top of `s3_chain_t`, WSABUF≡iovec, coalescing of adjacent chunks), signals → named events + a waiter thread, timer cap 500 ms; the event backend is select/WSAPoll first (sufficient for the client, FD_SETSIZE=64 does not matter), IOCP behind a flag; sockets are created with `WSA_FLAG_OVERLAPPED` from the start; build clang-cl/mingw + OpenSSL 3.5 from vcpkg (DEPS-QUIC.md §7.3). The skill is `c-win32`.
- **License**: all new code is BSD 2-clause (project owner's copyright); adapted nginx files keep `Copyright (C) Nginx, Inc.` + our line; at the root of the repo — `LICENSE` + `THIRD-PARTY-NOTICES.md`. This is functionally the same permissive class as OpenSSH's (the OpenBSD license ≈ ISC ≈ BSD-2).
- The directory was renamed `project/ssh3-cpp` → `project/ssh3-c` (the "cpp" in the name no longer matches the language).

## 3. Tracks: common framework, server, client

The layers `core/event/os/quic/h3` are common and symmetric for client and server. Divergence starts at the `ssh3/` layer:

| № | Layer | Server | Client |
|---|------|--------|--------|
| 1 | Common (P0–P3) | core/event/os/quic/h3 — one codebase, two binaries | the same |
| 2 | `ssh3/` + `app/` | accept-loops, auth-verifiers (`authorized_identities`, `getpwnam`/shadow, JWT/Basic), exec/shell/PTY (termios), sftp-subsystem with jail, forward handling, agent UDS, login banner | dial+0-RTT, known_hosts TOFU, auth-providers (password/JWT-file/JWT-agent), session pump (stdin/stdout/PTY raw+resize), forward initiators, ControlMaster, sftp-client with resume |

Build: two binaries `ssh3` and `ssh3-server` from one codebase (similar to `cmd/ssh3`, `cmd/ssh3-server` in Go).
