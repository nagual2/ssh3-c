# BENCH: копирование файлов — ssh3-c / Go-форк / ssh2 / rsync (v4 и v6 раздельно)

Дата: 2026-11-03. Скрипт: [`bench/copy-compare.sh`](../bench/copy-compare.sh).
Стенд: WSL2, loopback, tmpfs (/dev/shm), 64 МиБ payload, 3 замеренных раунда + 1
прогревочный (отбрасывается), sha256 обеих сторон на каждом переносе.

Реализации: ssh3-c 0.5.8 (`--sftp`), Go-форк (`-transfer`), OpenSSH scp (ssh2),
rsync 3.2.3 поверх ssh2. Один ed25519-ключ во двух форматах (PKCS8 для JWT,
OpenSSH для sshd/scp/rsync); демоны dual-stack (`[::]`), семейство выбирается
литералом операнда (`127.0.0.1` / `[::1]`).

## Результаты (медиана MB/s, проверенные раунды)

| Реализация | v4 push | v4 pull | v6 push | v6 pull |
|------------|---------|---------|---------|---------|
| **ssh3-c** | **110.9** | **117.7** | **108.5** | **112.1** |
| Go-форк | 23.9 | 31.8 | — (1) | — (1) |
| ssh2 (scp) | 116.2 | 120.6 | 117.3 | 150.8 |
| rsync (по ssh2) | 109.1 | 131.8 | 109.9 | 136.9 |

(1) Операнд трансфера Go-форка парсит `user@host:remote` наивным split по
двоеточию — скобочная форма `[::1]` не выражается («too many ':' separators»).
v6-exec у Go работает (URL-форма скобки несёт); дыра — именно в операнде
трансфера. Зеркально в Rust (`transfer.rs`, тот же парс) — см. «Rust» ниже.

## Выводы

1. **ssh3-c держит уровень ssh2/rsync на bulk-копировании**: 108–118 MB/s
   против 116–151 (ssh2) и 109–137 (rsync) — разница в пределах шума цикла,
   обе стороны loopback. v4 и v6 симметричны.
2. **Go-форк отстаёт в 4–5 раз** (24–32 MB/s) — узкое место его sftp-насоса
   (согласуется с прошлыми бенчами B7/B8-эры).
3. rsync по ssh2 — в пределах scp (дельта-протокол на свежем файле вырождается
   в сплошную передачу).

## Находки (не бенч-дефекты)

| № | Находка | Куда |
|---|---------|------|
| 1 | Операнд трансфера Go и Rust не выражает скобочный v6-литерал (наивный `split(':')` в обоих; exec-нога через URL-форму — работает) | Паритет-заметка в план Rust/форка; решение владельца |
| 2 | Rust-клиент сырой для стенда: загрузчик identity отвергает и PKCS8, и OpenSSH-формат ключа («PEM Base64 error») | PARITY.md Rust-репо (по решению владельца; руст-ноги в бенче opt-in через `--impls rust`) |
| 3 | C-клиент: эпoll на `/dev/null`-stdin без `-n` даёт EPERM («the console init failed») — бенч-ноги ездят с `-n` | Известная семантика (та же, что в `-f`-волне) |

## Воспроизведение

```sh
bench/copy-compare.sh --size-mib 64 --rounds 3
```

CSV: `$WORK/results/copy.csv` (по умолчанию `/tmp/copybench/results/copy.csv`).
