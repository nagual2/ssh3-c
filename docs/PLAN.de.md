## 1. Zielposition: „OpenSSH unter Linux-Systemen“

Ziel des Projekts: ssh3-c soll sich in Linux-Systemen eine Position analog zu OpenSSH erobern, mit entsprechender Lizenz. Was das konkret bedeutet:

| Nr. | Merkmal OpenSSH | Ziel ssh3-c | Status |
|---|-----------------|-------------|--------|
| 1 | Sprache — reines C | C17 | entschieden (2026-10-01) |
| 2 | Lizenz — permissiv (OpenBSD/ISC-Familie, ohne Copyleft) | eigener Code — BSD-2; entlehnter nginx-Code — BSD-2 (kompatibel); `THIRD-PARTY-NOTICES.md` | entschieden |
| 3 | Abhängigkeiten — nur Systembibliotheken (libcrypto, zlib) | nur `libcrypto` (OpenSSL ≥3.5 QUIC API) | entschieden (DEPS-QUIC.md) |
| 4 | Protokollschicht — eigener Code des Projekts | QUIC+H3 — unser Quelltext (Adaption nginx) | entschieden |
| 5 | Pakete in Distributionen, man-Seiten, systemd-Units | deb/rpm/apk/ipk, man, socket-Aktivierung | Phase P7 |
| 6 | Koexistenz mit Vorgängern (OpenSSH ersetzte telnet/rsh, löschte sie nicht) | ssh3 — eigenständiges Paket neben OpenSSH, kein Ersatz | Phase P7–P8 |
| 7 | Qualität, akzeptabel für security-Teams der Distributionen | fuzzing, sanitizers, Audit (R2), Interop-Matrix | Phasen P6+ |

Protokollspezifikation — `SSH 3.0 alpha-00` (Primärquelle — Go-Implementierung francoismichel/ssh3, der Fork nagual2 hat das Protokoll geerbt). IETF-Track geschlossen (2026-10-16, Entscheidung des Besitzers): der Upstream ist tot, draft-michel-remote-terminal-http3-00 abgelaufen — die Spezifikation wird zum Dokument des Projekts (rev nagual2/1, Etappe (0) P8 in §4).

## 2. Sprache und Lizenz (Fixierung der Entscheidungen)

- **C17** (ersetzte das frühere „C++20“): beide Referenzen (OpenSSH, nginx) — C; libstdc++ fehlt in Basissystemen (Alpine base, embedded/OpenWrt); C-ABI ist stabil. Polymorphismus — Funktionszeiger (Muster `ngx_connection_t`), keine Klassen.
- **Windows-Client (P9) — ebenfalls C17** (vom Piloten bestätigt 2026-10-10): portabler Code ist bereits C17 mit Coverage (ctest/fuzz/Interop), neu nur os-Schicht und CLI-Gerüst; C++ erneut abgelehnt — das Argument libstdc++ gilt für Windows nicht, doch es gibt keinen Gegenvorschlag: alle Systemschnittstellen (WinSock, ConPTY, named pipes) sind C-API. Portmodell — nach dem Vorbild `src/os/win32/` nginx 1.31.7 (6 147 Zeilen reinem C): Plattformspezifik voll in `src/os/win/` (Spiegel von `os/unix/`), `s3_errno.h` mit `S3_E*`→Win-Codes (`S3_EAGAIN=WSAEWOULDBLOCK`), I/O-Tabelle auf Funktionszeigern (WSARecv/WSASend über `s3_chain_t`, WSABUF≡iovec, Zusammenlegung benachbarter), Signale → named events + Wartethread, Timer-Cap 500 ms; event-Backend — select/WSAPoll zuerst (Client reicht, FD_SETSIZE=64 unwichtig), IOCP hinter Flag; Sockets sofort `WSA_FLAG_OVERLAPPED`; Build clang-cl/mingw + OpenSSL 3.5 aus vcpkg (DEPS-QUIC.md §7.3). Skill — `c-win32`.
- **Lizenz**: gesamter neuer Code — BSD 2-clause (Copyright des Projektbesitzers); adaptierte nginx-Dateien behalten `Copyright (C) Nginx, Inc.` + unsere Zeile; ins Repo-Root — `LICENSE` + `THIRD-PARTY-NOTICES.md`. Das ist funktional dieselbe Klasse von Permissivität wie bei OpenSSH (OpenBSD-Lizenz ≈ ISC ≈ BSD-2).
- Verzeichnis umbenannt `project/ssh3-cpp` → `project/ssh3-c` (cpp im Namen entspricht der Sprache nicht mehr).

## 3. Tracks: gemeinsames Gerüst, Server, Client

Die Schichten `core/event/os/quic/h3` sind gemeinsam und symmetrisch für Client und Server. Die Verzweigung beginnt auf der Schicht `ssh3/`:

| Nr. | Schicht | Server | Client |
|---|---|---|---|
| 1 | Gemeinsam (P0–P3) | core/event/os/quic/h3 — ein Code, zwei Binaries | identisch |
| 2 | `ssh3/` + `app/` | accept-Loops, auth-Verifizierer (`authorized_identities`, `getpwnam`/shadow, JWT/Basic), exec/shell/PTY (termios), sftp-Subsystem mit jail, forward-Verarbeitung, agent UDS, login banner | dial+0-RTT, known_hosts TOFU, auth-Provider (password/JWT-Datei/JWT-Agent), session pump (stdin/stdout/PTY raw+resize), forward-Initiatoren, ControlMaster, sftp-Client mit resume |

Build: zwei Binaries `ssh3` und `ssh3-server` aus einer Codebasis (analog `cmd/ssh3`, `cmd/ssh3-server` in Go).
